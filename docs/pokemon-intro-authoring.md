# 「このポケモンってどんなポケモン？」記事制作メモ

## 基本方針

- 対戦初心者向けの、シーズンに依存しにくい入門記事にする。育成論にはしない。
- 現在の10記事を文章品質・情報量・粒度のお手本にする。
- 記事対象とフォームは、Champions由来の既存metadataと固有のpokemon/form IDで区別する。名前の文字列だけで判定しない。
- メガ、リージョン、ロトム等、既存metadataで独立した対戦フォームになっているものは別記事にできる。見た目だけの差はデータ生成段階で対象外にする。
- 役割タグは `content/pokemon-roles.ts` の共通定義から選び、記事ごとの自由な名称は増やさない。
- 「よく使う技」はポケモンらしさが伝わる代表技を選ぶ。タイプ・威力・命中・技説明は既存move metadataを再利用し、記事側には技IDとそのポケモン固有の役割説明だけを保存する。
- 使用率順位は初回の制作順だけに使い、本文には持ち込まない。シーズンが変わっても完成記事を削除しない。
- 既存の「ポケモン使い方解説」は現時点では削除しない。

## 1 batchの標準フロー

1. `data/pokemon-intro-production-plan.json` と現在の記事IDを比較し、次の未完成batchを取得する。
2. 対象10匹のChampionsデータから、タイプ・種族値・特性・フォーム・learnset・代表技を確認する。
3. 必要な場合だけ基本的な役割を追加調査する。
4. 既存記事を参考に執筆し、共通role definitionsからタグと代表技を選ぶ。
5. シーズン依存の採用率・流行・順位を本文へ書かない。
6. 10記事を全文監査し、tests・typecheck・lint・production buildを実行する。
7. 完成batchをGitHub mainへ反映し、GitHub上の反映を確認してセーブポイントにする。

原則10匹ずつ追加する。batchの一部だけ記事がある場合は「一部完成」と扱い、残りIDを同じbatchから作る。既存batchは保持し、新規Champions対象は未記事化かつ未計画なら計画末尾へ追加する。

既存10記事を含めて約30記事になった時点で大量追加を止め、文章品質・タグ粒度・テンプレートの単調化・情報量を人間がレビューする。レビュー後に品質が安定していれば、20匹単位への拡大を検討する。
